**Checkpoint cadence:**
- Create a checkpoint after each passing green test, not just week boundaries.
- A checkpoint is one line per test: `hook <name> — PASS`.
- At week boundaries, before summarising, run a **determinism sweep** on any new protocol-level code:
  - `grep -rn "as f64\|as f32\|f64::\|f32::" crates/` — flag any floating-point in deterministic paths
  - `grep -rn "Instant::now\|SystemTime::now\|thread_rng\|rand::random" crates/` — flag wall-clock/random sources in protocol logic
  - `grep -rn "thread_local!\|RefCell\|SPEC_DEVIATION\|conformance shim" crates/*/src/` — any match must be justified as NOT being a test shim in library code
  - Verify `default` feature in each crate's `Cargo.toml` does not enable any `mock-*` or `*-shim` features
  - Verify all new `HashMap`/`HashSet` usages in protocol code don't leak iteration order into consensus decisions
  - Verify every `pub fn` that returns `HashMap` cannot feed into deterministic state (should use `BTreeMap` or sorted `Vec` instead)
  - [MANUAL] For any new graph/clustering/connectivity algorithm, add a transitive-closure test case: three-or-more hop chains must produce the same cluster as direct connections
  - In state-machine transaction handlers, grep for `if let Some.*get_mut` — every such expression must have an `else` arm that rejects, not silently skip
  - [MANUAL] In state-machine transaction handlers, verify the **validate-then-mutate** ordering: every mutation must be preceded by all validations. Scan for state mutated before a subsequent `?`/`return` path can exit without completing related mutations
  - After adding a new in-memory entity collection (HashMap/Set) to the state machine, verify that `compute_state_root()` includes it — grep for the new field in the `compute_state_root` implementation
   - After any code field rename that changes a type's semantic meaning (e.g., `pct`→`per_mil`, single-value→pair), grep all spec `.md` files for the old field name to catch documentation drift
   - After adding or modifying any protocol struct, verify every field is populated in at least one non-test production path — grep the field name across `crates/*/src/` to ensure it's set somewhere (not dead weight)
   - [MANUAL] For every state-machine transaction handler (functions named `execute_*`), trace the handler body to ensure the handler's intended effect actually mutates state — not just validates inputs and returns Success without persisting
   - Extend the floating-point determinism grep to spec files: `grep -rn "f64\|f32" docs/04-specifications/` — flag any floating-point types in spec data structure definitions that must be deterministic
    - For any spec document that claims to define a protocol subsystem (has a §1 heading), verify it has §1.3 Data Structures and §1.4 State Transitions (or equivalent structural sections per TEMPLATES.md) — missing sections are a structural gap flag
- [MANUAL] For any priority/comparison logic where enum discriminants are compared numerically, write a test with at least two different priority levels verifying the comparison direction is correct (not inverted)
- [MANUAL] For any lifecycle with a challenge/dispute/contest phase, write a negative test that exercises the challenge then asserts the finalization/acceptance is blocked
- [MANUAL] For any function that accepts a trust_stage/role/stage parameter, write a test with at least two different stage values verifying behavior differs appropriately
- When `snapshot_state()` exists as a separate serialisation path from `compute_state_root()`, verify it includes all the same collections — grep both functions for the full set of collection iterators and key prefixes and confirm they match
- [MANUAL] For any constructor that captures an identity/ID/peer field, verify the captured value is the intended remote value (not accidentally using `self` when `other` was intended) — write a test asserting every identity/ID field in the constructed object
- [MANUAL] For any protocol formula using a percentage value below 1% (e.g., 0.1%), verify the type can represent it: u8(0-100) cannot represent fractional percentages — use per-mil (u16, basis points) instead
- For any authorization/validation path that checks for the presence of required state (key_binding, nonce tracking, balance cache), verify the system fails CLOSED (denies) when state is absent — not open (allows). Grep for `is_none()\|is_err()` conditionals in validation paths and confirm the default branch is restrictive.
- Grep for `panic!()` and `assert!()` in production (non-test) code — every instance must be justified or replaced with a `Result` return. Focus on `src/` files (not `tests/`) and flag any that could crash under edge-case inputs.
- [MANUAL] In async code with shared state protected by `RwLock`/`Mutex`, verify that two separate lock acquisitions on the same guard within a single code path are merged into one atomic operation. Consecutive `.write().await` on the same lock is a TOCTOU risk.
- When the same logic (quota check, state serialization, validation) is implemented in two different code locations, verify both are kept in sync or refactor to a single source of truth with shared calls. Grep for duplicated `Vec<QuotaEntry>` or `fn compute_` definitions.
- [MANUAL] Verify that API keys, tokens, private keys, and other secrets are not persisted in plaintext to databases (SQLite, state KV), log output, or serialised state. Redact sensitive fields before any persistent storage path.
- For any `AtomicBool`/`Atomic*` used for cross-thread signaling (shutdown, cancellation, pause), verify the load uses at least `Ordering::Acquire` and the store uses at least `Ordering::Release`. `Ordering::Relaxed` provides no happens-before guarantee across threads.
- **Vaporware guard:** After adding a new `TxType` variant, `TaskStatus` variant, or struct field that claims to implement a spec feature, grep its name across `crates/*/src/` (excluding tests). Zero non-test production code paths = VAPORWARE. Either implement the behavior or remove the type before continuing.
- **checked-math overflow guard:** For any `checked_mul`/`checked_div` chain ending in `unwrap_or(0)`, verify overflow produces the correct economic outcome — defaulting to zero may silently erase adjustments. Use `saturating_mul` in the upstream operation or `unwrap_or(u128::MAX)` with a downstream cap to ensure overflow does not collapse to a no-op.
- **truncating-cast guard:** Grep for `as u32\|as u16\|as u8` casts in protocol code where the source expression is a wider integer type (most commonly `u64`, `usize`, `u128`). Every truncating cast must be preceded by a bounds check (at minimum `debug_assert!`) or use `u32::try_from(value).unwrap_or(u32::MAX)` — silent truncation of block heights, fees, or scores introduces non-obvious edge cases at chain scale.
- **async-JoinHandle guard:** Grep for `let _ = handle.await` or other patterns that discard tokio `JoinHandle` results in production main/loop code — a panicked spawned task is silently swallowed and the parent continues as if the task stopped cleanly. Match on the result and log at error level for the `Err` branch.
- **mutex-poison guard:** Grep for `if let Ok(guard) = lock.lock()` in production code that lacks an error/warning branch in the `else`/`Err` arm — a poisoned mutex indicates a prior panic in a held critical section, and masking it without logging loses crash-forensics for all downstream diagnostics.
- **dead-field read-side guard:** Extend guard #16 (field-population check) with a read-side sweep. After verifying a struct field is populated in at least one production path, grep the field name for read-sites (non-test, non-`new`/`default`/`Default::default()`) — if no non-test code path ever reads the field, it is dead weight in the struct and should be removed or the consuming logic added.
- File as `docs/08-handoff/latest/checkpoint-YYYY-MM-DD.md`.
- **duplicate-drift guard:** When a canonical data table, constant set, or validation logic exists in two separate source locations (e.g., the same quota matrix in two modules), grep for the duplicate and verify they match or refactor to a single source of truth. Two divergent copies of the same canonical data are a consensus-split vector — any diff between them will produce different validation results on different code paths.
- **block-timestamp guard:** Block timestamps in all consensus, driver, and BFT code paths must be deterministically derived from block height (not `SystemTime::now()` or any wall-clock source). Grep `crates/hyperfluid-consensus/src/` for `SystemTime::now|Instant::now` — any hit in a block production or proposal-building path is a determinism violation that will cause divergent block hashes across validators.
- **quorum-ceil guard:** For any formula that computes a supermajority threshold as `(total * fraction_numerator) / fraction_denominator`, verify integer division uses ceiling semantics — `div_ceil` or `(total * numerator + denominator - 1) / denominator`. Floor division can produce off-by-one quorum values at small cardinalities, allowing a minority to pass proposals when they should not.
- **parameter-unit guard:** When a function parameter is multiplied by a count of another unit (e.g., `cooldown_epochs * block_time_s`), verify the parameter's actual unit matches the computation's intent. A parameter named `block_time_s` (seconds per block) being multiplied by `cooldown_epochs` to produce a block-height cooldown is wrong — the multiplier should be `epoch_length_blocks` (blocks per epoch). Audit every site where a named parameter is multiplied by a differently-named quantity.
